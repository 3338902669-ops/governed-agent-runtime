# Known findings

Every accepted limitation lives here with a severity, a disposition and a review date. An empty
register would be a claim that none exist, which is why `scripts/gate.mjs` and
`controlPlane.audit()` print what they can see rather than only what passes.

| ID | Severity | Finding | Disposition | Review by |
|---|---|---|---|---|
| F-GAR-01 | medium | **Evidence store duality.** Runtime evidence lives in the hash-chained ledger; the governance queue's `task.evidence` array is only written by the engine's `completeStage`. This prototype does not drive the governance stage machine to completion, so the two stores disagree. | disclosed: `audit()` reports it as an observation (`EVIDENCE_STORE_DUALITY`, `GOVERNANCE_STAGE_NOT_ADVANCED`) instead of claiming consistency. Closing it means driving the stage machine from the runtime - the next phase. | 2026-12-01 |
| F-GAR-02 | medium | **Cross-agent handoff is not expressible.** The governance engine has no reassign API (`claimTask` requires `task.assignedAgent === agent`, and `recoverTask` clears the lock without changing the assignee), so a handoff here is a same-agent epoch bump that supersedes the old session. | open in the layer below: the runtime gets the property that matters (the superseded session and its grants are dead). A real reassignment needs a governance-level `assign` operation. | 2026-12-01 |
| F-GAR-03 | low | **In-process state, not a security boundary.** Sessions, grants, approvals and the ledger are in memory. An agent that can execute arbitrary code in the same process is not contained by any of this. | accept by design, stated in the README: enforcement against an unwilling agent needs signed state or an external authorisation service. | 2027-01-01 |
| F-GAR-04 | low | **The root of trust is outside the gate.** `bootstrapTrust` lets a named human principal evaluate and release the seed artifacts, because there is no agent above the first artifact. | accept with disclosure: it is the only ungated state change, it is recorded as `trust.bootstrap` in the ledger, and no agent role can reach it. | 2027-01-01 |
| F-GAR-05 | low | **Rigor is not yet mapped onto runtime evidence floors.** The governance engine enforces L1/L2/L3 evidence floors; the runtime checks evidence shape (E1 needs command, exit code, revision) but does not apply the per-level floor to its own facts. | open: the runtime currently defers rigor to the governance task record. A shared floor table is the fix. | 2026-11-15 |
| F-GAR-06 | low | **The grant TTL is wall-clock over an injectable clock.** A caller that supplies its own clock controls expiry; tests rely on this deliberately. | accept: the clock is a seam for testing determinism, and a production runtime would read a monotonic source. | 2027-01-01 |
| F-GAR-07 | low | **`assertIntegrity` revokes as a side effect while the gate evaluates.** A policy rule mutates the registry when it detects tampering, so `authorize()` is not a pure function of its context. | accept: the revocation is idempotent, it is what kills the other sessions on the same artifact, and the alternative (detect and continue) is worse. Recorded because "pure gate" is otherwise an over-claim. | 2026-12-01 |
| F-GAR-09 | medium | **The nine findings from the security scan are fixed but not independently re-verified.** The high one (revocation reinstated by `evaluate`) and six medium caller-supplied-identity findings were fixed and confirmed by the implementer re-running the scanner's own POC, plus tests A18/A19. No independent round has re-examined the hardened tree. | open: a fresh scan is running; an independent 天枢 card on the hardened revision is the next step. Until then the correct reading is "fixed, pending independent confirmation". | 2026-11-15 |
| F-GAR-10 | low | **`internals: true` hands out the raw state objects**, whose shapes differ from the read-only facades (`ledger.rows` is an array on the raw object but a function on the facade). A verifier had to work around this. | accept for now: the privileged surface is a test seam, but the shape mismatch is a real wart. | 2026-11-15 |
| F-GAR-08 | low | **Approval identity is unauthenticated.** `approvedBy` is a string supplied by the caller, exactly as in Agent Orchestra's F-003. | accept: the queue and the session table are local state under the operator's control; attribution is by convention. | 2027-01-01 |
